**구현 순서와 완료 조건**

초기 목표는 수익성 주장보다 데이터→전략→모의 주문→대사의 수직 경로를 정확하게 만드는 것이다. 아래 일정은 1인 개발의 계획 예시이며 데이터 접근·전략 복잡도·기존 코드에 따라 달라진다. 모의 관찰 기간과 수익성 검증 기간은 개발 기간과 별도다.

설계 이후의 실제 진행 현황·검증 범위는 [로컬 MVP](04-implementation.md), [LLM·KIS 모의 어댑터](05-integrations.md), [진단·후보 등록·shadow 관찰](06-shadow-operations.md)에 기록했다. 현재 관찰용 버전 등록과 영속 중단까지 실행 가능하다. 실제 한투 연결·주문 계약 확인과 실시간 전진 관찰은 남아 있다.

사용자 요청에 따라 자동 주문보다 [종목 선정·전략 로직·자동 개선](08-selection-and-improvement.md)을 우선했다. v0.5는 주문 없는 연구 사이클을 완료했으며 실제 전 시장 입력·과거 종목 상태·상품별 비용 검증은 별도 데이터 연결 작업이다.

| 순서 | 산출물 | 완료 조건 | 계획 예시 |
| --- | --- | --- | --- |
| 0 | 시장·주기·자율성·자본·위험 계약 | 거래 대상·실행창·평가 기준·실거래 차단 기본값 확정 | 1~2일 |
| 1 | KIS 조회 어댑터·API 계약 맵·데이터 스냅샷 | 모의/실전 분리, 날짜 분할·중복·결측·토큰·호출 제한 확인 | 3~5일 |
| 2 | 단순 기준 전략·비용 포함 평가 | 시점 누수 없음, 익일 실행 가정 명시, 원장·수익률 재현 | 3~5일 |
| 3 | 모의 주문 OMS·리스크·대사 | 접수/체결 구분, 부분 체결·취소·불명 상태·재시작 복구 | 5~8일 |
| 4 | 제한된 후보 생성·실험 기록·평가 게이트 | 기존 버전 유지 가능, 모든 시도 기록, 최종 평가 격리 | 4~7일 |
| 5 | 실시간 shadow·모의투자 관찰 | 운영 결함 해결, 체결 비용·결정 차이·대사 보고서 확보 | 4~8주부터 관찰 |
| 6 | 검토 가능한 소규모 실거래 배포 묶음 | 계좌·자본·위험 한도·중단 정책·고정 버전·승인 확보 | 증거가 충분한 시점 |

실거래 전환은 현재 요청에 포함하지 않는다. 단계 6은 구현·평가·보고서를 완성한 뒤 검토할 경계이며, 지금 필요한 승인이 아니다.

**첫 번째 수직 경로.** 후보를 생성하는 LLM을 붙이기 전에 다음 하나를 끝낸다.

1. 사전 지정 유니버스의 원주가·조정주가·거래일을 수집하고 버전이 있는 스냅샷을 만든다.
2. 단순 룰 한 개가 입력 데이터와 파라미터만으로 결정되도록 구현한다.
3. 같은 데이터를 비용 포함 백테스트에 넣고, 동일 전략이 실시간 shadow에서도 같은 시점·입력으로 같은 신호를 내는지 확인한다.
4. 한투 모의 환경에서 작은 주문 의도 하나를 현금 예약→전송→접수→체결/취소→잔고 대사로 추적한다.
5. 전략·데이터·비용·실행 설정 해시, 모든 상태 전이, 수수료·실현/미실현 손익이 연결된 보고서를 만든다.

**핵심 검증 시나리오.** 구현 시 모의 브로커/기록 재생을 이용해 장애를 주입한다. 순수 함수와 예시를 그대로 반복하는 테스트보다 실제 자금·포지션 오류를 유발할 경계를 우선한다.

| 상황 | 확인할 불변조건 |
| --- | --- |
| 주문 전송 직후 타임아웃·프로세스 종료 | UNKNOWN으로 복구하고 재전송을 막음. 주문·체결 조회로 해결 전 신규 노출 정지 |
| 주문 접수 후 DB 기록 실패 | 전송 전 저장 기록·대사를 이용해 복구. 브로커 주문이 누락된 상태로 재주문하지 않음 |
| 두 스케줄러의 동시 실행 | 계좌별 단일 작성자·unique 의도·현금 예약으로 중복 전송 방지 |
| 부분 체결 뒤 취소, 취소 중 추가 체결 | 누적 체결·취소 잔량·현금·보유 수량이 일치 |
| WebSocket 중복·역순·연결 단절 | 체결을 이중 반영하지 않음. REST 대사로 누락 보완 |
| API 호출 제한·토큰 만료 | 조회 backoff·토큰 갱신 단일화. 주문을 일반 조회처럼 재시도하지 않음 |
| 휴장·VI·거래정지·오래된 호가 | 신규 노출 차단, 정해진 대응만 수행 |
| 입출금·분할·분배금·수동 매매 | 보유 수량·현금·수익률 귀속이 보존됨 |
| 종가 확정 전 실행·미래 특징·미래 기억 | 데이터 계층에서 거절. 같은 종가로 즉시 체결한 성과를 만들지 않음 |
| 후보 평가 코드가 위험 한도를 변경 | 파일/DB 권한으로 거절. 평가기의 기준은 유지 |
| 최종 구간 실패 후 재최적화 시도 | 소비된 평가 구간 표시·승격 보류, 새 독립 증거 요구 |
| 롤백 시 기존 포지션·미체결 존재 | 신규 의사결정 중지→대사→전환 계획→동일 리스크 경로 |

**권장 디렉터리.** 아래는 확장을 위한 목표 구조다. 현재 로컬 MVP는 동일한 책임을 src/trading_agent의 평면 모듈로 구현했다.

```text
src/trading_agent/
  contracts/       # CandidateManifest, Decision, OrderIntent, BrokerEvent
  data/            # 수집·시점 카탈로그·기업행위·유니버스
  broker/kis/      # 단일 API 계약 맵·인증·REST·WS
  strategies/      # 검토된 룰·모델, 주문 없는 목표 비중 출력
  research/        # 가설·후보 생성·예산·시점 기억
  evaluation/      # 시간순 분할·Lean 어댑터·비용·통계·재현
  portfolio/       # 정수 수량·현금·노출 계산
  risk/            # 별도 소유의 고정 정책
  execution/       # OMS·예약·아웃박스·상태 전이
  reconciliation/  # 주문·체결·보유·현금 대사
  registry/        # 실험·승인·배포·아티팩트 해시
  operations/      # 스케줄러·보고서·정지·복구
skills/            # 프로젝트 전용 절차, 권한의 근거로 사용하지 않음
configs/           # 비밀 없는 설정·정책 참조
tests/             # 장애 주입·시간 정렬·계좌 불변조건
```

**첫 설정의 기본 자세.** mode는 paper, live_enabled는 false로 시작한다. risk_policy_id와 deployment_approval이 비어 있으면 실거래 프로세스가 시작되지 않아야 한다. 자격증명은 연구 프로세스·저장소·리포트에 들어가지 않게 분리한다. 기존 공식 샘플이나 MCP의 live 키가 우연히 주입되더라도 계좌·환경·승인 묶음 검증을 통과해야 주문이 가능하도록 한다.

**설계 확정에 필요한 선택.** 지금 구현을 막는 승인 요청이 아니라, 이후 구체화할 입력이다.

- 국내 주식/ETF 또는 미국 주식, 일봉/스윙 또는 분봉, KRX만 또는 별도 거래소 포함 여부.
- 파라미터 개선만 또는 코드·모델 후보까지, 사람이 승격 승인 또는 검증 정책에 의한 자동 승격.
- 전용 계좌 여부, 시작 자본, 종목·총 노출·일일 손실·드로다운 한도, 긴급 축소 정책.
- 기존 데이터·코드·모델·서버, 데이터 예산·LLM 예산, 과거 유니버스·기업행위 자료의 공급원.

시장·주기·자율성의 답이 없으면 현재 설계의 국내 ETF·일봉·승격 승인 가정을 유지한다. 자본·손실 한도의 답이 없으면 이를 추정해 실거래하지 않고 paper/shadow 범위에서 구현한다.
