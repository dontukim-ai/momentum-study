# v10 1단계: 장중 매매 비용 측정 (2026-10-26 제안, 2026-10-26 사용자 승인)

v3~v8은 일봉·월 1회 판정만 시험했다. 일봉 데이터(FSC·OpenDART)만 있었고, 엔진도 일봉 기준으로 만들어졌기 때문이다. 장중(분봉) 전략은 하루 거래가 많아 전진 표본이 빨리 쌓인다. 대신 왕복 비용이 수익을 먼저 깎는다. 저장소 비용 설정으로는 왕복 약 73bp다(수수료 1.5bp×2 + 매도세 20bp + 슬리피지 25bp×2). 분봉 전략을 사전 등록하기 전에, **그 비용이 실제로 얼마인지부터 잰다.** 이 단계는 측정만 한다. 전략·백테스트·주문은 없다.

## 1. 묻는 것

1. 대형 국내 주식형 ETF를 장중에 사고팔면 왕복 비용이 얼마인가(호가 스프레드 + 수수료 + 세금)?
2. 시간대별로 얼마나 다른가(시가 직후, 장중, 마감 직전)?
3. 최우선 호가 잔량이 연구 자본 규모의 주문(1백만·1천만·1억 원)을 감당하는가?
4. KIS로 당일 1분봉을 빠짐없이, 얼마나 늦게 받을 수 있는가?

## 2. 대상 (결과 전 고정)

| 종목 | 이름 | 넣은 이유 |
|---|---|---|
| 069500 | KODEX 200 | 기존 연구의 기준 ETF, 거래 최대 |
| 102110 | TIGER 200 | 같은 지수, 다른 운용사(스프레드 비교) |
| 229200 | KODEX 코스닥150 | 코스닥 대표 |
| 278530 | KODEX 200TR | 분배금 재투자형, 거래가 적은 쪽의 비교 |
| 005930 | 삼성전자 | 주식 비교(매도세 있음) |

레버리지·인버스 ETF는 넣지 않는다(기존 설계 02-design 초기 범위). 국내 주식형 ETF는 매도 시 증권거래세가 없는 것으로 알고 있다. **세율과 KIS 실제 수수료는 측정 전에 공식 자료로 확인하고 문서에 적는다.**

## 3. 수집 방법

**REST 조회로 시작한다(권장).** kis-agent의 실계좌 읽기 전용 클라이언트(`KisRealReadOnly`)에 조회 경로 두 개만 더한다. 주문 경로는 더하지 않는다.

| 조회 | KIS API (실호출로 확인 필요) | 주기 |
|---|---|---|
| 호가 10단계 | 주식현재가 호가/예상체결 `/uapi/domestic-stock/v1/quotations/inquire-asking-price-exp-ccn` (`FHKST01010200`) | 정규장 중 종목별 10초마다 |
| 당일 1분봉 | 주식당일분봉조회 `/uapi/domestic-stock/v1/quotations/inquire-time-itemchartprice` (`FHKST03010200`) | 장 마감 뒤 15:40에 한 번(30개씩 이어 받기), 장중에는 매시 정각에 한 번 |

- 요청량: 5종목 × 10초 = 초당 0.5건이다. 기존 최소 간격(0.7초)과 KIS 제한 안에 든다.
- 저장: 응답 원문을 수신 시각과 함께 `data/kis/intraday/<날짜>/`에 둔다(Git 제외, 재배포 금지). 변환기가 CSV(시각, 매수·매도 1~10호가와 잔량)로 바꾼다.
- **웹소켓(실시간 체결 `H0STCNT0`·호가 `H0STASP0`)은 미룬다.** 승인 키 발급, 연결 유지, 새 의존성이 필요하다. 1단계 결과가 2단계로 갈 만할 때 다시 판단한다.
- 맥이 정규장(09:00~15:30) 내내 켜져 있어야 한다. 실행은 맥 세션에서 하루 단위로 띄운다.

## 4. 기간

10거래일. 시간대별 분포를 보기에 충분하고, 월초·월말과 선물·옵션 만기일(목요일)이 하나 이상 들어가게 시작일을 고른다.

## 5. 측정 지표 (결과 전 고정)

- **스프레드:** (매도1 − 매수1) ÷ 중간가, bp. 종목별 30분 구간마다 중앙값과 90% 분위수. 동시호가(08:30~09:00, 15:20~15:30) 조회는 따로 보고하고 장중 값에서 뺀다.
- **왕복 비용 추정:** 장중 스프레드 중앙값 + 수수료 × 2 + 매도세(ETF 0, 주식은 확인한 세율). 시장가로 사서 바로 판다고 가정한 값이다. 지정가 체결 가능성은 이 단계에서 다루지 않는다.
- **잔량:** 최우선 매수·매도 호가 잔량의 원화 금액 중앙값. 1백만·1천만·1억 원 주문이 1호가 안에서 채워지는 조회 비율을 함께 낸다.
- **분봉 완전성:** 정규장 381개(09:00~15:30) 대비 받은 개수, 빈 분, 장중 조회에서 직전 분봉이 나타나기까지 걸린 시간.
- 조회 실패·지연(응답까지 1초 초과) 건수.

## 6. 다음 단계로 가는 기준 (결과 전 고정)

ETF 네 개 각각의 **장중(09:30~15:00) 왕복 비용 추정 중앙값**으로 판단한다.

- **5bp 이하인 ETF가 하나 이상:** 2단계(분봉 전략 사전 등록 + KIS 모의계좌 전진 검증) 설계안을 쓴다.
- **5~15bp만 있음:** 결과만 보고하고, 진행 여부는 사용자가 정한다.
- **모두 15bp 초과:** 장중 전략은 이 ETF들로 하지 않는다. 결과만 기록한다.

5bp와 15bp는 문헌이나 이전 결과에서 나온 값이 아니다. 장중 예측 가능한 움직임이 보통 몇 bp 수준이라는 일반적 이해에 기댄 제안값이다. 승인할 때 바꿀 수 있지만, 결과를 본 뒤에는 바꾸지 않는다.

## 7. 필요한 변경 (승인 요청)

1. `apps/kis-agent/src/trading_agent/kis_real.py`의 `READ_ROUTES`에 호가·당일분봉 두 조회를 더하고, 응답을 정규화하는 읽기 함수를 둔다. 가짜 transport로 단위 테스트한다. **주문 경로, `REAL_CAPITAL_LIMIT`(1M), `MarketProfile.capital_cap`은 바꾸지 않는다.**
2. 저장소 `tools/kis_intraday_probe.py`(수집, 하루 단위 실행)와 `tools/kis_intraday_report.py`(지표 계산)를 만든다. 보고 도구는 합성 응답으로 테스트한다.
3. 키는 지금처럼 환경변수(`KIS_APP_KEY`·`KIS_APP_SECRET`·`KIS_ACCOUNT`)에서만 읽고, 저장소·로그·클라우드에 남기지 않는다. 응답에 키가 섞이면 저장하지 않는다(기존 수집기 규칙과 같다).

kis-agent 변경은 사용자 허락이 필요한 범위다. 이 문서의 승인(2026-10-26)으로 위 두 조회 추가를 허락받았다. 주문 경로는 허락 범위가 아니다.

## 8. 하지 않는 것

실주문과 모의주문, 전략 신호, 백테스트, holdout, 원자료 커밋, 웹소켓은 이 단계에서 하지 않는다. KRX data.krx·KIND 자동 수집도 하지 않는다.

## 9. 한계

- 10초 조회는 그 사이의 호가 변화를 놓친다. 스프레드는 표본 값이다.
- 스프레드는 1호가 즉시 체결 비용이다. 큰 주문이 여러 호가를 먹는 충격 비용은 잔량 비율로만 가늠한다.
- 2주는 한 시장 국면이다. 변동성이 큰 날의 비용은 다를 수 있다.
- 비용이 낮다고 장중 전략이 수익을 낸다는 뜻은 아니다. 이 단계는 "해볼 수 있는가"만 답한다.

## 10. 일정 (승인 후)

2. 맥에서 실호출 한 번으로 응답 형식 확인(1종목, 장중)
3. 10거래일 수집
4. 보고서(이 문서 §11에 결과 기록)

## 11. 구현 (2026-10-26)

- **확인한 사실.**
  - API 경로·TR ID·응답 필드는 KIS 공식 예제 저장소(`koreainvestment/open-trading-api`, `examples_llm/domestic_stock`)로 확인했다. 호가는 `output1`의 `askp1..10`·`bidp1..10`·`askp_rsqn*`·`bidp_rsqn*`·`aspr_acpt_hour`이다. 분봉은 `output2`의 `stck_bsop_date`·`stck_cntg_hour`·`stck_prpr`·`stck_oprc`·`stck_hgpr`·`stck_lwpr`·`cntg_vol`이며, 한 번에 최대 30개, 당일만 준다.
  - 매도세: 국내 상장 ETF는 세법상 신탁형 펀드라 매도 시 증권거래세가 없다(KB자산운용 ETF 세금 안내). 개별 주식은 0.20%다. 보고 도구는 ETF 0bp, 005930 20bp로 계산한다.
  - **KIS 실제 수수료는 아직 확인하지 않았다.** 보고 도구의 `--commission-bps`(기본 1.5bp, 편도)를 계좌의 실제 요율로 바꿔 실행한다.
- **변경.**
  - `trading_agent/kis_real.py`: `READ_ROUTES`에 `asking`(`FHKST01010200`)·`minute`(`FHKST03010200`)을 더했고, 계좌 정보 없이 보내는 시세 조회로 묶었다. `asking()`·`minute_bars()`는 응답 원문을 돌려준다. 주문 경로와 `REAL_CAPITAL_LIMIT`은 그대로다.
  - `tools/kis_intraday_probe.py`: 하루 수집 도구다. 08:30~15:30에 `--interval`(기본 10초)마다 호가를 읽고, 10~15시 정각마다 최근 분봉을 읽는다. 15:31 이후에는 그날 분봉 전부를 30개씩 거슬러 읽는다. 응답은 수신 시각·응답 시간과 함께 `data/kis/intraday/<날짜>/`의 JSONL에 덧붙인다. 키가 섞인 응답은 쓰지 않고 멈춘다. 오류는 기록하고 계속하되, 30번 연속 실패하면 멈춘다. 이미 있는 날짜 폴더는 `--resume` 없이는 거부한다.
  - `tools/kis_intraday_report.py`: §5 지표와 §6 판정을 계산한다. 아무것도 쓰지 않는다.
- **검증.**
  - 가짜 KIS·가짜 시계로 하루(08:20 시작)를 끝까지 돌리고, 그 출력으로 보고서와 판정을 계산했다.
  - 키 유출 시 멈추는지, 연속 실패 시 멈추는지, 판정 경계값(5bp·15bp)을 테스트로 확인했다.
  - kis-agent에는 새 조회의 TR ID·계좌 정보 미포함·입력 거부·주문 거부 테스트를 더했다.
- **실행.** 맥에서 거래일 08:30 전에 `uv run --extra agent python tools/kis_intraday_probe.py`를 띄운다. 10거래일 뒤 `uv run python tools/kis_intraday_report.py data/kis/intraday/<날짜>... --commission-bps <실제 요율>`을 실행한다.
