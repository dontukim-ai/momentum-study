# 세부 개발 계획과 완료 조건

기준: [블루프린트](README.md). **이번 요청은 이 계획의 문서화다. 아래 미착수 항목을 이번에 구현했다고 표시하지 않는다.** 현황 기준은 `577fede`, 코드 기준은 `74e07e9`다.

## 1. 상태와 작업 관리

| 표기 | 뜻 |
| --- | --- |
| 완료 | 현재 코드와 해당 범위의 회귀·합성 증거가 있음 |
| 부분 | 일부 기반 코드는 있으나 목표 입력·운용 연결·증거가 부족 |
| 미착수 | 설계 대상이며 해당 기능을 완성한 구현 없음 |
| 보류 | 사용자 범위에 따라 진행하지 않음 |

작업 완료에는 소스·계약 버전, 실패 사례 회귀, 실행 명령, 산출물, 현황 갱신이 필요하다. 경제 계산 변경은 실패하는 회귀부터 작성한다. 기존 골든이나 승격 임계값을 결과에 맞춰 바꾸지 않는다. 테스트 통과와 실데이터 검증 완료는 별도 칸으로 기록한다.

## 2. 단계별 통과점

```mermaid
flowchart LR
    M0[현재: 합성 자동 연구] --> M1[실제 시점 데이터 계약]
    M1 --> M2[비용·기업행동·경제 평가 보강]
    M2 --> M3[새 데이터 독립 검증]
    M3 --> M4[상시 연구·전진 관찰 운영]
    M4 --> M5[후속 모의 계좌 운용]
    M5 -. 현재 후순위 .-> M6[별도 실전 운용 단계]
```

| 단계 | 선행 조건 | 단계 완료 증거 |
| --- | --- | --- |
| M0 합성 연구 | 현재 코드 | 네 단계·승격/유지·복구·중복 차단 재현. **완료** |
| M1 실제 입력 | DATA-01~06 | 출처·정정·상태·달력·행동이 묶인 실제 소규모 입력과 품질 보고 |
| M2 경제 평가 | M1 + FIN-01~04 | 상품별 비용·신호/회계·결제·기말 정책의 손계산 및 실제 자료 대사 |
| M3 독립 검증 | M2 + RES-01~03 + LOOP-02, LOOP-03, LOOP-07 | 비교군·예산 계정·선택 후보·구간을 첫 실행 시각 전에 고정하고 새로운 자료에서 결과 보존. 증거 등급 E2 기록 |
| M4 연구 운영 | OPS-01~06 | 서비스 복구·데이터 중단·백업 복원·selector-bound 전진 관찰 증거 |
| M5 모의 운용 | M4 + ORD-01~02 | 실제 모의 서버에서 계좌·미체결·부분 체결·응답 유실 대사 |
| M6 실전 운용 | 별도 후속 범위 + ORD-03~04 | 실제 계좌의 자본·위험·실행 계약을 검증한 운용 버전 |

M0의 연구 champion은 M4~M6의 운용 자격을 자동으로 얻지 않는다. 각 단계의 연구 결과·운영 준비·외부 서비스 검증 상태를 따로 기록한다.

**묶음 A: 데이터 적합성부터 확인.** DATA-01을 먼저 끝내고, 확인된 공급자 범위로 DATA-02/03의 소규모 예제를 만든다. 못 구한 필드는 명시하며 임의의 과거 값으로 채우지 않는다.

**묶음 B: 입력과 경제 계약을 연결.** DATA-04/05/06과 FIN-01/02를 구현해 실제 종목 소수의 종단 흐름을 만든다. 검증된 비용과 행동·달력을 가진 입력이어야 한다.

**묶음 C: 검증과 운영을 보강.** FIN-03/04, RES-01~03, OPS-01/02/04를 완료하고, 새로운 전진 구간을 등록한다. 수집·감시 프로세스의 건강 상태를 확인한 뒤 OPS-06 캠페인을 시작한다.

**묶음 L: 루프 구조(합성 데이터로 병행 가능).** 순서는 비교 계약·기준 전략·지표(LOOP-01, LOOP-03, RES-01, LOOP-07) → 후보 사전 고정과 예산(RES-03, LOOP-02) → 실패 기억 권한(LOOP-08) → 구간 예약·동시 사용(LOOP-09) → 연속 관찰·Release(LOOP-04, LOOP-05, LOOP-06)다. LOOP-09는 LOOP-05·LOOP-06과 함께 설계를 확정하되, 관찰을 실제 다음 사이클과 연결하기 전에 구현한다. LOOP-07은 RES-02와 함께 정책 v2로 묶는다. 이 묶음은 데이터 대기와 무관하게 시작할 수 있으나 기존 연구의 정책·소비 이력을 바꾸지 않는다.

**묶음 D: 실패를 이용하는 개선을 확대.** RES-04/05를 연결하고(실패 코드는 [루프 계약](loop-contracts.md) §9), 실제 근거가 확보되면 RES-06을 작은 모델부터 추가한다. LOOP-06 Release 계약은 OPS-05와 함께 정한다. 주문 개발은 이 묶음에 자동으로 포함하지 않는다.

고정 날짜 대신 단계 완료 증거로 진행한다. 현재 기본 최종 구간은 40거래일, 전진 shadow는 20거래일이다. 실제 전진 캠페인은 이 기간이 도착해야 끝나며, 공개된 과거 표본을 새 표본이라고 다시 부르는 방식으로 일정을 줄이지 않는다.

## 10. 변경·검증 규칙

데이터·비용·학습·위험·통계·개인 자본 설정의 변경을 분리한다. 정책 변경에는 이유·영향 전략·소비 이력·새 데이터 요구량을 기록한다. 모델 가중치·범위·seed 변경도 새로운 시도로 센다.

문서만 수정할 때는 링크·기본값·코드 근거·diff를 검증한다. KRX 연구 코드를 수정하면 통합 회귀와 KIS 앱 검사를 실행하고, 공통 회계 변경에는 필요한 골든·경제 대사를 추가한다. 미국 H1~H4 연구는 보류하며, 전체 저장소 테스트의 과거 통과 기록을 새로운 미국 연구 실행으로 표현하지 않는다.
