# 실데이터 공급원 결정과 필드표 (DATA-01)

상태: 초안. "확인" 열이 `미확인`인 항목은 PC에서 `tools/data_probe.py`로 실제 응답을 받아 확정한다. 클라우드 세션에서는 아래 공급원에 접속할 수 없다.

## 1. 결정

사용자 위임(2026-10-17): **무료 범위**에서 공급원을 고른다.

| 용도 | 공급원 | 선택 이유 | 대체 불가·한계 |
| --- | --- | --- | --- |
| 일별 시세(주식) | 공공데이터포털 금융위원회 주식시세정보 | 기준일별로 **그날 상장된 전 종목**을 준다. 이후 상장폐지된 종목도 과거 날짜 응답에 남아 생존 편향이 없다 | 이력 시작이 2020년 전후(미확인). 호가(bid/ask) 없음 |
| 일별 시세(ETF) | 공공데이터포털 금융위원회 증권상품시세정보 | 시장 ETF 기준 전략(RES-01)과 ETF 후보 | 위와 같음 |
| 상장폐지·관리종목·거래정지 이력 | KRX 정보데이터시스템 「이슈 통계」 화면(사람이 다운로드) | 지정일·해제일로 시점별 상태를 재구성 | API 없음, 자동 수집은 약관상 금지(2026-10-20 확인, §2.2) |
| 기업행동(분할·병합·감자·증자·배당) | OpenDART 공시검색·주요사항보고서 | 접수 시각이 있어 공개 시점(`available_at`)을 정할 수 있다 | 권리락일·지급일은 공시 본문에서 추출해야 하는 항목이 있음(미확인) |
| 실시간 운용 | KIS 조회 API | 당일 종가·호가를 제때 받는 유일한 경로 | 과거 상태 이력 없음. 검증 데이터로 쓰지 않음 |

유료 자료(FnGuide 등)와 KRX 정보데이터시스템 스크래핑은 이번 결정에서 제외한다. 이력이 부족해 사이클 수가 모자라면 그때 다시 검토한다.

## 2. 연구 입력 계약과의 대응

연구 입력(`ResearchInput`)은 세 파일이다: 가격 CSV(`session,symbol,open,high,low,close,volume,available_at,source`), 종목 상태 JSONL(`SecurityState`), 기업행동 JSON.

### 2.1 가격 CSV ← 금융위원회 주식·증권상품 시세

| 연구 필드 | 공급원 필드(추정) | 변환 | 확인 |
| --- | --- | --- | --- |
| session | `basDt` (YYYYMMDD) | 날짜 변환 | 확인(2026-10-19) |
| symbol | `srtnCd` (단축코드 6자리) | 그대로. 영구 ID는 `isinCd`로 따로 보관(DATA-02) | 확인(2026-10-19) |
| open/high/low/close | `mkp`/`hipr`/`lopr`/`clpr` | 원 단위 Decimal. **원시가**(분할일에 비율만큼 불연속, 아래 참조) | 확인(2026-10-19) |
| volume | `trqu` | 정수 | 확인(2026-10-19) |
| available_at | 응답에 없음 | §3 정보 시계 정책 | 정책 |
| source | 고정 문자열 `fsc-stock-price` / `fsc-etf-price` + 수집 manifest 해시 | | 정책 |
| (참고) 시장 구분 | `mrktCtg` (KOSPI/KOSDAQ/KONEX) | 종목 상태의 market | 필드 확인(2026-10-19) |
| (참고) 상장주식수·시가총액 | `lstgStCnt`, `mrktTotAmt` | 진단용. 신호에 쓰지 않음 | 필드 확인(2026-10-19) |

2026-10-19 확인(ETF, 활용가이드와 포털 시험 호출):
- 서비스는 V2다. ETF 경로 `https://apis.data.go.kr/1160100/GetSecuritiesProductInfoService_V2/getETFPriceInfo_V2`. 예전 `/service/GetSecuritiesProductInfoService/getETFPriceInfo` 경로는 V2로 발급된 키를 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(30)로 거부했다. 주식 경로는 같은 규칙의 `GetStockSecuritiesInfoService_V2/getStockPriceInfo_V2`다. 2026-10-19 맥 탐침에서 2024-06-03 기준 ETF 1페이지·주식 3페이지 모두 HTTP 200을 확인했다.
- ETF 응답 필드: `basDt, srtnCd, isinCd, itmsNm, mkp, hipr, lopr, clpr, vs, fltRt, trqu, trPrc, nav, mrktTotAmt, nPptTotAmt, stLstgCnt, bssIdxIdxNm, bssIdxClpr`. 위 표의 open/high/low/close/volume 대응이 ETF에서 확인됐다. 원시가 여부는 미확인.
- 요청: `numOfRows` 최대 10,000, 초당 30건, `beginBasDt`/`endBasDt`/`isinCd` 조회 조건이 있다.
- 이용허락: 공공누리 4유형(출처표시·상업적 이용 금지·변경 금지)이며 제3자 제공·재배포가 금지된다. 수집 원본과 파생 파일을 저장소·공유 위치에 올리지 않는다(`artifacts/`, `data/krx/`는 Git 제외). 상업적 이용은 KRX Data Marketplace 구매 대상이다.

실데이터 확인(2026-10-19, 사용자 맥, 2024-05-01~06-28 주식):
- 주식 응답 필드: `basDt, clpr, fltRt, hipr, isinCd, itmsNm, lopr, lstgStCnt, mkp, mrktCtg, mrktTotAmt, srtnCd, trPrc, trqu, vs`.
- 수집 43평일 → 달력 39세션, 휴장 평일 4일(2024-05-01 근로자의 날, 05-06 대체공휴일, 05-15 부처님오신날, 06-06 현충일)로 실제 휴장과 일치. 세션당 2,805~2,817행.
- 2024-06-03 변환: 2,810행, ISIN 2,810개, 코드 변경 0건. 행 선별 2,676행 통과, 134행 격리(전부 `NONPOSITIVE_PRICE`, 0 가격 행). 거래정지 종목의 0 시가로 추정하며 미확인이다. 채우지 않고 격리한다.
- `available_at`은 `2024-06-03T09:00:00+00:00`(= 18:00 KST)로 기록됐다.

원시가·거래정지 확인(2026-10-19, 사용자 맥, 2024-04-01~05-10):
- **원시가다.** 에코프로(086520, 1:5 액면분할, 신주상장 2024-04-25)의 `clpr`은 517,000 → 108,100, 이수스페셜티케미컬(457190, 1:5, 2024-05-02)은 339,500 → 61,000으로 분할비율만큼 떨어졌다. `lstgStCnt`는 정확히 5배가 됐다.
- `vs`·`fltRt`는 거래소가 조정한 기준가 대비 값이다(에코프로 분할일 `fltRt` +4.55%, `clpr`로 계산하면 -79%). 수익률은 `clpr`로 직접 계산하고 `vs`·`fltRt`는 신호에 쓰지 않는다. 분할일의 큰 원시 수익률은 기업행위로 설명되지 않으면 DATA-05a가 `ABNORMAL_RETURN`으로 격리한다.
- **거래정지일에도 행이 온다.** `mkp`·`hipr`·`lopr`·`trqu`가 모두 0이고 `clpr`에는 직전 종가가 그대로 들어 있다. 공급자가 채워 넣은 값이므로 가격 행으로 쓰면 결측을 채운 것과 같다(규칙 3 위반). DATA-02c부터 변환기는 이런 행을 가격 CSV에 넣지 않고 `no_trade.jsonl`(기준일·종목·ISIN·보고된 종가)로 따로 남긴다. 거래 상태(정지) 재구성의 근거로 쓴다. 0 시가에 거래량이 있는 행처럼 이 패턴에 맞지 않는 0 가격은 그대로 두어 `NONPOSITIVE_PRICE`로 격리한다.

가격 변환(DATA-02b): `momentum.krx.fsc_prices`와 `tools/fsc_prices.py`는 탐침이 저장한 시세 JSON 페이지를 네트워크 없이 가격 CSV(`prices.csv`), 기준일별 단축코드–ISIN–종목명(`identities.jsonl`), 페이지 해시·행 선별 결과(`manifest.json`)로 바꾼다. `available_at`은 §3의 사전 등록 가정(기준일 18:00 KST, `MarketProfile.historical_bar_available`)이고, `source`는 `fsc-stock-price:<페이지 SHA-256>` 형식이다. 공급자 값은 고치지 않는다. 0이나 빈 가격도 그대로 옮겨 DATA-05a 행 선별이 격리한다. 기준일의 행 수가 `totalCount`와 다르거나, 페이지가 중복되거나, 한 기준일에 같은 단축코드가 두 ISIN으로 나오면 변환 전체를 거부한다. 단축코드 재사용·변경은 `identity_changes`로 보고만 하고 병합하지 않는다. 실행: `uv run python tools/fsc_prices.py --kind stock --pages <탐침 out>/fsc_stock/<날짜>/page-*.json --out data/krx/fsc/<이름>`. 근거는 합성 페이지 회귀이며, 실제 페이지 변환 결과는 사용자 PC 실행으로 확인한다. 출력은 재배포 금지 자료이므로 `data/krx/`(Git 제외)에 둔다.

시가가 0이거나 비어 있는 행(거래 없음·정지)은 **채우지 않는다**. 가격 행을 만들지 않고 DATA-05 품질 코드로 격리한다(CLAUDE.md 3번: 결측 시가 → 매수 취소).

### 2.2 종목 상태 JSONL ← KIND + 시세 응답

| 연구 필드 | 원천 | 변환 | 확인 |
| --- | --- | --- | --- |
| symbol | 시세 `srtnCd` | | 미확인 |
| status | KIND 상장폐지일·거래정지 지정/해제 | NORMAL / SUSPENDED / DELISTED 이벤트 | 미확인 |
| asset_type | 공급 API 종류(주식시세=STOCK, ETF시세=ETF) | ETN·기타는 OTHER | 정책 |
| market | 시세 `mrktCtg` | | 미확인 |
| managed | KIND 관리종목 지정/해제 | 지정일~해제일 true | 미확인 |
| caution | KIND 투자주의·경고·위험 지정 | 지정 기간 true | 미확인 |
| leveraged / inverse | ETF 종목명·기초지수 정보 | 이름 규칙만으로 정하지 않는다. 확인 불가 종목은 후보에서 제외 | 미확인 |
| bid / ask | **무료 이력 없음** | §4 | 대체 불가 |
| effective_at / available_at | KIND 지정일·공시 시각 | 공시 시각이 없으면 지정일 장 마감 후로 보수적으로 둔다 | 미확인 |

**출처 확인(2026-10-20, 맥에서 브라우저로 읽기만 함, 가입·로그인 없음):**
- KRX Open API(`openapi.krx.co.kr`, 2010년 이후)는 관리종목·시장경보(투자주의·경고·위험)·거래정지·상장폐지 이력을 **제공하지 않는다**(FAQ: "해당 데이터는 모두 API로는 제공되고 있지 않습니다", "거래정지 여부를 구분하는 항목을 제공하지 않습니다"). 종목기본정보(상장일·시장구분·상장주식수, 기준일 `basDd`별, 상장폐지일 없음)는 있다. 약관(2025-12-26): 키당 하루 10,000회, 비상업(개인 연구) 목적만, 제3자 제공 금지, 계약 종료 후 이용 금지.
- 이력은 정보데이터시스템(`data.krx.co.kr`) 「이슈 통계」 화면(매매거래정지 내역, 관리종목 지정 내역, 투자주의환기종목 지정 내역, 투자주의·경고·위험종목 지정 내역, 상장폐지종목 현황)에만 있다. 약관(2026-08-29) 제10조②가 **"자동화 수단을 이용하여 정보를 무단 수집·복제·배포하는 행위"를 금지**하고, KRX 공지(2026-06-01)는 화면 검색·다운로드 기능만 쓰라고 한다(pykrx 등 사설 라이브러리 금지, IP 차단). KIND에는 자체 약관이 없고 공통 법적고지가 무단 복제·배포를 금지한다. robots.txt는 세 사이트 모두 없다(404).
- **결정(2026-10-20):** 자동 수집기를 만들지 않는다. 사람이 data.krx 화면의 다운로드 기능으로 받은 파일을 `data/krx/kind/`(Git 제외)에 두고 파서가 읽는다. 받은 파일은 재배포하지 않는다.
- **수동 파일 실측(2026-10-20 다운로드, CP949, 날짜 `YYYY/MM/DD`):** 관리종목·매매거래정지는 「이슈 통계」에서 **현황만** 받을 수 있다(과거 이력은 개별종목 화면에서 종목별로만). 관리종목 현황 182행(최초지정일 2023-03-23~), 거래정지 현황 123행, 상장폐지 3개 파일(2019-10-01~2024-09-27, 증권구분이 섞임: 주권만 쓴다, 지유온 중복 1건, `이전상장후_종목코드`는 운용사·발행회사라 쓰지 않는다).
- **정책 1(2026-10-20 사용자 결정, DATA-07b `tools/securities.py`):** 상태(정상·정지·폐지)와 시장은 시세에서 추론하고(DATA-07a) KRX 정지·폐지 목록은 대조만 한다. `managed`는 현황의 최초지정일부터 참, 그 밖은 거짓이며 스냅샷 이전의 거짓은 **미검증**이다. `caution`은 이력이 없어 거짓이다. 모든 레코드의 `source`에 "managed/caution history unverified before snapshot (policy 1)"을 남겨 결과에 따라가게 한다. 이 입력으로 낸 결과는 투자 판단 근거로 쓰지 않는다. 최초지정일이 빈 행(티케이지애강)은 채우지 않고 보고서에 보류로 남긴다.

### 2.3 기업행동 JSON ← OpenDART

PC 탐침 결과(2026-10-17, 기준일 2024-06-03, `pblntf_ty=B` 주요사항보고 31건)로 공시목록(`list.json`) 필드를 확인했다.

| 공시목록 필드 | 확인된 형태 | 쓰임 | 확인 |
| --- | --- | --- | --- |
| `rcept_no` | 14자리 숫자 문자열, 앞 8자리가 접수일 | 공시 고유 ID. 정정공시도 별도 번호 | 확인 |
| `rcept_dt` | YYYYMMDD, **시각 없음** | `available_at`의 날짜(§3) | 확인 |
| `stock_code` | 6자리. 31건 중 4건 빈 값(비상장) | 단축코드 연결. 빈 값은 연구 대상 아님 | 확인 |
| `corp_code` | 8자리 DART 고유번호 | `corpCode.xml`(약 3.6MB)로 종목코드와 연결 | 확인 |
| `corp_cls` | Y/K/N/E | 유가증권/코스닥/코넥스/기타 | 확인 |
| `report_nm` | 예: `주요사항보고서(영업양수결정)`, `[기재정정]…` | 행동 종류 분류, 정정 여부 | 확인 |
| `rm` | 비고 문자 조합(예: 공, 정, 공정). 31건 중 9건 빈 값 | 진단용 | 확인 |

공시목록에는 비율·권리락일·지급일 같은 **세부 값이 없다**. 세부 값은 주요사항보고서 종류별 상세 API에서 받아야 한다(DATA-01b 탐침으로 필드 확인).

| 연구 필드 | 원천 | 확인 |
| --- | --- | --- |
| security_id | 공시목록 `stock_code` | 확인 |
| action_type | `report_nm`의 보고서 종류(무상증자·유상증자·감자·주식분할/병합 등) | 분류 규칙은 DATA-02 |
| ex_date / pay_date | 종류별 상세 API(권리락일·신주배정기준일 등) | 미확인 |

  - **무상증자·감자 정책 B(2026-10-20 사용자 결정, FIN-02l 원장):** 무상증자는 `bonus_issue`(`split_ratio`=1주당 신주 수, `ex_date`=권리락일, `pay_date`=신주 상장일). 권리락일 시가 시점 보유 수량 × 비율의 내림만큼 **상장 전 미상장 주식**으로 잡고, 상장일까지 팔 수 없지만 종가로 평가해 `positions_value`에 넣는다. 상장일에 보유로 옮긴다. 감자는 `capital_reduction`(`split_ratio`=감자 후 남는 비율 < 1, `ex_date`=재상장일)로 그날 수량을 내림해 줄이고 평가 단가를 비율로 나눈다. 두 경우 모두 **단주는 가치 0으로 버린다**(실제는 회사별 기준가로 현금 정산). 순자산은 버린 단주 가치만큼만 줄고 늘지 않는다. 평가기는 이 날 직전 계획 주문을 비율로 바꾸지 않고 `cancelled_action_uncertainty`로 취소한다. 유상감자(현금 환급)는 아직 지원하지 않는다.

I 유형 목록에는 자회사 건만 있다. 상세 API 응답의 날짜는 `"2024년 04월 17일"`, 숫자는 콤마 문자열, 없는 값은 `"-"`다. `nstk_ascnt_ps_ostk`는 1주당 **추가** 배정 주식 수라 기준가는 `1 + 배정수`배 움직인다(스튜디오미르 5주 → 5.993, 권리락 04-05 = 기준일 04-08의 T+2 규칙). 감자결정에는 자기주식 소각(가격 변동 없음), 유상소각(현금 상환), 무상병합(가격 변동)이 섞여 있다. `tools/capital_actions.py`는 원 공시가 이벤트 시가 전에 공개됐고 **거래소 기준가 조정(FIN-02a)이 비율을 확인할 때만** 행위를 만든다. 무상증자는 확인 실패 시 미해결(SNT에너지: 2주 배정인데 기준가 2.755배), 감자는 유상이면 미해결, 가격 변동이 없으면 건너뛴다. 같은 날 분할 행위가 이미 있으면 중복으로 건너뛴다. **감자 확인은 상장주식수 비율로 한다(FIN-02p):** 재상장 기준가는 시초 결정 절차로 정해져 감자 비율과 2~24% 어긋났다(2023-10~2024-06 10건, 예: 003060 기대 0.1 → 0.1045). 그래서 재상장일은 `lstgStCnt` 비율이 남는 비율에 0.5% 안으로 맞고 기준가가 내려간 첫 날로 정한다. 허용 오차는 넓히지 않았고, 정확히 맞아야 하는 관측값(주식 수)으로 바꿨다. 자기주식 소각은 보유 수량을 바꾸지 않으므로 건너뛴다. 실데이터 결과: 2023-10~2024-06 감자 8건이 주식 수 비율로 정확히 확인됐다(가격 배수는 0.2~9% 차이). **거래정지 중 재상장**(006380·111870·214870·226360: 시가·거래량·등락 0인 행에서 주식 수와 종가만 비율대로 바뀜)은 `detect`가 무거래 행을 건너뛰어 놓쳤으므로, `detect_halted_share_changes`가 무거래 행의 주식 수 변화를 `HALTED_SHARE_CHANGE`로 따로 보고하고 감자 확인에 쓴다(FIN-02q). 최대주주 한 명만 대상인 불균등 감자(067390)와 실행되지 않은 감자(비트플래닛)는 미해결로 남는다. **상세 API는 최초접수일로 조회하고 그 공시의 최신 정정본을 정정본 접수번호로 돌려준다**(프로브잇 2023-12-27 원공시 → 2024-01-12 정정본, 맥 실측). 그래서 상세 값은 응답 항목의 접수번호를 가진 공시에만 붙이고(그 공시의 공개 시각 기준), 값이 정정본으로 대체된 원공시(목록 비고 `정`)는 건너뛴다. 정정 공시는 자기 접수일로는 조회되지 않으므로 원공시 요청만 보낸다.
  - **신제도 결산배당의 지급일 미정(2026-10-20 사용자 결정: 미해결 유지):** 2023년 결산부터 주총 뒤 기준일을 정하는 회사 중 지급예정일·주총일이 모두 '-'인 공시는 이사회결의일 + 1개월이 배당락일보다 앞선다(2024 상반기 23건, 예: 현대차 기준일 02-29, 계산 지급일 02-25). 주총일을 모르면 법정 지급 시한의 상한을 정할 수 없으므로 '기준일 + 1개월' 같은 추정 규칙을 만들지 않고 행위를 만들지 않는다. 해당 종목은 배당락 하락만 반영돼 수익률이 배당수익률만큼 보수적으로(낮게) 나온다. 실제 지급일을 주는 공식 출처를 찾으면 채운다.
  - 같은 종목·기준일·배당구분의 공시는 묶는다. 금액과 공개 시각은 **배당락일 시가 이전에 공개된 마지막 공시**에서 가져온다. 그 뒤 공시가 금액을 바꿨으면 행위를 만들지 않는다(평가 시점에 알 수 없던 정보).
  - 자회사 공시, 현물배당, 보통주 금액 없음은 행위를 만들지 않는다. 종류주식 금액은 보통주에 붙이지 않고 증거에만 남긴다.
  - **늦게 공시된 배당(정책 A, 2026-10-20 사용자 결정):** 2023 결산까지의 관행은 기준일(12-31)과 배당락일(12-27)이 먼저 오고 배당액 공시가 1~2월에 나온다. 실데이터(2024 상반기)에서 1,064건이 이 경우였고, 삼성전자·KT&G 등 고배당 대형주가 대부분이었다. 배당락일 시가에는 금액을 알 수 없으므로 일반 기업행위로 만들 수 없지만, 빼면 배당락 하락만 반영돼 고배당주 수익률이 연 2~5% 과소평가된다. 그래서 `late_cash_dividend`로 만든다. **권리는 배당락일 시가 시점 보유 수량**으로 정하고, **금액은 가장 이른 공시가 공개된 뒤 첫 거래일(시가 ≥ 공개 시각)에 미수로 계상**하며, 현금은 지급일(정책 A)에 들어온다. 이후 공시가 금액을 바꾸면 행위를 만들지 않는다. 연구 입력에서는 `ResearchInput.late_dividends`이고, 공개 전에는 `prefix`와 지문에 들어가지 않는다. 늦은 배당이 없는 입력의 지문은 바뀌지 않는다. 원장은 매 거래일 시가 시점 보유 수량을 기록해 권리를 계산한다(`Ledger.holdings_at_open`, `accrue_entitlement`).
  - **세금:** 원장은 배당을 세전 금액으로 적립한다. 배당소득 원천징수(국내 거주자 15.4%)는 반영하지 않으므로 순수익이 과대 계산된다. 세금 반영은 FIN-01 비용·세금 계약에서 정한다.
  - 실데이터 연구 입력의 `supplied-actions-complete` 선언은 짝 없는 자회사 공시 확인, 무상증자·감자가 끝나기 전까지 쓰지 않는다.

**주의(정보 시계):** 상세 조회를 원 공시 접수일로 요청했는데 그 기간 밖의 접수번호(예: 2024-07-10 접수)가 돌아온 사례가 있다. 상세 API가 나중의 정정본을 돌려줄 수 있다는 뜻이다(추정). 그대로 쓰면 미래 정보가 과거 결정에 섞인다. 따라서 상세 행의 `available_at`은 **원 공시가 아니라 그 행의 `rcept_no` 접수일 18:00 KST**로 두고, 원 공시보다 늦은 접수번호는 정정 이벤트로 따로 기록한다(FIN-02 구현 조건).
| split_ratio / cash_amount | 종류별 상세 API(배정비율·감자비율 등) | 미확인 |
| available_at | `rcept_dt`에 시각이 없으므로 **접수일 18:00 KST**로 둔다. 장중 공시였더라도 그날 결정에는 쓰지 않는다(보수적) | 정책 |

정정공시는 원공시를 덮어쓰지 않고 새 이벤트로 쌓는다(DATA-02). 현금배당은 주요사항보고가 아니라 거래소 공시·사업보고서 항목이라 이번 공시목록에 나오지 않는다. 배당 원천은 DATA-02에서 따로 정한다.

공시 이벤트 원장(DATA-02a): `momentum.krx.dart_events`와 `tools/dart_ledger.py`는 탐침이 저장한 공시목록 JSON 페이지를 네트워크 없이 검증·분류하여 추가 전용 JSONL로 기록한다. 접수일 18:00 Asia/Seoul부터 `as_of`에 노출하며 원본 파일 SHA-256을 보존한다. 같은 접수번호의 내용 변경은 배치 전체를 거부하고, 정정공시는 별도 번호로 유지한다. 빈 종목코드는 보존하되 `listed_only()`에서는 제외한다. `uv run python tools/dart_ledger.py --pages <탐침 out>/dart/<기간>/page-*.json --ledger data/krx/dart_events.jsonl`로 실행한다. 완료 근거는 가짜 페이지를 사용한 합성 회귀 범위이며 실데이터 검증은 미완료다. 비율·권리락일 추출과 연구용 CorporateAction 생성은 후속 작업이다. 원장 경로 `data/krx/`는 Git에서 제외한다.

## 3. 정보 시계(available_at) 정책

공공데이터 시세는 연계받은 날로부터 **영업일 하루 뒤 13:00 이후**에 갱신된다(금융위원회 증권상품시세정보 활용가이드, 2026-10-19 확인. 금요일 자료는 다음 월요일). 그대로 쓰면 t일 종가가 t+1일 장 시작 전에 보이지 않아, 전일 종가로 수량을 정하는 현재 체결 규칙과 맞지 않는다.
- **제공 범위(2026-10-20 확인):** 주식 시세 V2는 2020-01-02부터 행이 있다(2,475건). 2019-01-02·2018-01-02·2015-01-02는 오류 없이 0건이다. 그래서 0건 응답은 휴장일과 범위 밖을 구별하지 못한다. 관측 달력은 첫 행 있는 날보다 앞선 빈 날을 휴장이 아니라 `before_coverage`로 보고하고 첫 관측 거래일에서 시작한다(DATA-03b). 백테스트 시세 구간은 2020-01-02 이후다.

결정(사전 등록, 과거 검증용):
- 과거 구간의 t일 시세 `available_at`은 **t일 18:00 KST**로 둔다. 같은 값이 그날 거래소 종가로 이미 공개됐다는 가정이다. 이 가정은 입력 묶음의 `basis`에 명시한다.
- 이 가정은 E1(예약 과거 구간) 증거에만 쓴다. E2·E3 실시간 증거는 실제 수신 시각을 `available_at`으로 쓰며, 당일 종가는 KIS로 받는다.
- 정정된 시세가 나중에 들어오면 원래 값을 바꾸지 않고 정정 이벤트로 남긴다(DATA-05).

수집과 달력(DATA-06a, DATA-03a):
- `tools/fsc_collect.py`는 날짜 범위의 평일마다 금융위 V2 시세를 모든 페이지까지 받아 `<root>/<kind>/<날짜>/`에 원본 페이지와 `fetch.json`(요청일·수신 시각·totalCount·페이지 해시)을 남긴다. 페이지 합계가 totalCount와 맞을 때만 임시 디렉터리를 원자적으로 이름 바꿔 확정한다. 확정된 날은 다시 받거나 덮어쓰지 않는다. 요청 간격 기본 1초, 네트워크 오류만 2·4초 후 최대 3회 시도한다. 인증키는 환경변수에서만 읽고, 키를 되돌려준 응답은 저장하지 않으며, 오류 메시지에 URL을 넣지 않는다. 기본 경로 `data/krx/raw/fsc`(Git 제외).
- `tools/fsc_calendar.py`는 수집된 주식 일자로 관측 달력(`calendar.json`, 연구 입력 형식)을 만든다. 행이 있는 평일은 세션이다. 빈 응답은 휴장일 수도 있고 아직 공개 전(다음 영업일 13:00 이후 공개)일 수도 있으므로, **그 뒤 날짜에 행이 있을 때만** 휴장으로 확정한다. 미수집 또는 미확정 평일이 나오면 그 앞에서 달력을 멈춘다. 주말은 요청하지 않는다.
- 미래 달력(최종 구간 예약용)은 이 방법으로 만들 수 없다. 거래소 공식 휴장일 공지가 필요하며 후속 작업이다.
- 근거는 가짜 공급자를 쓴 합성 회귀다. 실제 수집은 사용자 PC 실행으로 확인한다.

## 4. 호가(spread) 공백

현재 선정 규칙은 bid/ask가 없으면 `SPREAD_UNAVAILABLE`로 후보에서 뺀다. 무료 과거 호가 자료가 없으므로 실데이터를 그대로 넣으면 모든 종목이 빠진다. 과거 호가를 현재 호가로 채우지 않는다(implementation-plan의 원칙).

2026-10-18 사용자 결정으로 **선택지 1을 채택**했다(FIN-01a, 합성 회귀 범위 구현). `SelectionPolicy.spread_mode`의 기본값 `quoted`는 기존 호가 필터를 유지한다. 사전 등록한 `historical_unavailable`은 bid/ask가 없을 때만 호가 제외를 생략하고 `spread_source=unavailable_preregistered`를 표시한다. 실제 호가가 있으면 `spread_source=quoted`로 표시하고 기존 spread 계산과 넓은 호가 제외를 적용한다. 유동성·변동성·가격·이력·시장·상태 필터는 유지하며 호가를 생성하거나 결측을 채우지 않는다.

이 모드의 `AgentPolicy`는 편도 slippage **최소 25bp**를 강제한다. 결과를 보기 전에 정한 보수값으로, 최소 가격 1,000원대의 1원 호가 단위 반 틱 이상과 기본 5bp의 차이를 덮는다. 선정 정책 digest가 평가 계약 ID에 반영되므로 다른 모드의 결과를 동일 계약으로 비교할 수 없다. status·tick의 기존 policy 요약에서 모드를 확인한다.

현재 주문 경로는 `SelectionPolicy`를 받지 않으며 공통 연구 수량 계획에는 주문 거부 검사를 넣지 않는다(주관자 결정). 대신 관찰 release에 근거 사이클의 `spread_mode`와 `execution_eligible`을 동결한다. `historical_unavailable`은 실행 자격 false이며 주문 권한은 여전히 없다. 후속 ExecutionRelease는 실행 자격 false를 거부해야 한다([루프 계약 §11](loop-contracts.md#11-release--s4--운용-loop-06)).

**선택지 2(전진 수집)**는 병행 과제로 남긴다. KIS로 실제 수신 시각의 호가를 수집하고, 충분한 이력이 쌓인 뒤 실제 호가 조건의 E2/E3 검증에 사용한다. 25bp 하한은 실제 비용 적합성·실데이터 검증 완료를 뜻하지 않는다.

## 입력 묶음(DATA-04a)

오프라인 연구 입력은 다음 불변 디렉터리로 공개한다. 필수 파일은 `prices.csv`, `securities.jsonl`이며 행동·세션·달력은 기존 입력 계약대로 선택 사항이다.

```text
<root>/
  staging/<임시 이름>/
  bundles/<bundle_id>/
    prices.csv
    securities.jsonl
    actions.json       # 선택
    sessions.json      # 선택
    calendar.json      # 선택
    manifest.json
  CURRENT              # bundle_id 한 줄
```

manifest 스키마 v1은 `schema_version`, 파일별 `sha256`·`bytes`를 가진 `files`, 기업행동 기준 `basis`, 자유 메타데이터 객체 `sources`, clock의 `created_at`, `bundle_id`를 기록한다. ID는 정규화 JSON `{schema_version, files, basis, sources}`의 SHA-256이며 생성 시각은 제외한다. 같은 파일·basis·sources 재발행은 기존 manifest와 디렉터리를 그대로 유지한다.

`created_at`은 시간대가 있는 시각이어야 하며 staging에서 검증한다. 잘못된 시각도 입력 파싱 실패와 같이 새 버전 디렉터리나 CURRENT를 공개하지 않는다.

`momentum-agent bundle-publish --bundle ROOT --csv PRICES --securities STATES`에 선택 `--actions`, `--sessions`, `--calendar`, `--source-meta JSON파일`, `--corporate-action-basis`를 지정할 수 있다. 발행은 staging 복사 → 해시·manifest 작성 → 기존 `read_input`으로 ResearchInput 생성 검증 → bundles 디렉터리 rename → 임시 CURRENT 파일의 `os.replace` 순서다. 실패 시 staging을 정리하고 기존 CURRENT와 bundles를 보존한다. 발행 원본 파일도 복사 동안 동일 수집 snapshot으로 유지해야 한다.

수집기는 파일을 직접 덮어쓰지 않고 검증된 묶음만 발행하며, 연구 worker는 `run --bundle ROOT`로 묶음만 읽는 운영 규칙을 따른다. 기존 직접 경로 실행은 호환성을 위해 유지하지만 bundle과 함께 지정할 수 없다. worker는 tick마다 CURRENT를 한 번 읽고 그 버전의 전체 파일명·크기·해시와 manifest ID를 대조한 뒤 파싱한다. 중간 포인터 교체는 진행 중 읽기에 영향을 주지 않는다. 누락·추가·불일치는 `Input bundle integrity failure`로 중단한다. 공개 디렉터리는 수정·삭제하지 않으며, 결과 JSON에 `input_bundle: {bundle_id, created_at}`을 남긴다. 이 ID는 파일 공개 버전이며 기존 연구 지문이나 DB·commitment 계약을 대체하지 않는다. 현재 근거는 합성 회귀이며 실제 공급원 수집·상시 운영 검증은 후속이다.

## 데이터 품질 코드와 격리(DATA-05a)

품질 검사는 두 단계다. 어느 단계도 값을 추정해 채우거나 원본을 고치지 않는다.

1. **원시 행 선별** `momentum-agent quality-screen --csv RAW --output DIR`: 가격 CSV를 `Bar`로 만들기 전에 행 단위로 검사해 `prices.accepted.csv`와 `prices.quarantine.csv`(원래 줄 번호·사유 코드·원래 값)로 나눈다. 원본 파일은 읽기만 한다. `quality-screen.json`에 원본·통과본 sha256과 코드별 개수를 남긴다. 통과본을 `bundle-publish`의 `--csv`로 쓰고, 이 보고서 해시를 `--source-meta`에 기록한다.
2. **행 간 검사** `momentum-agent quality-report --bundle ROOT`(또는 `--csv --securities`): 연구 입력 전체를 검사해 `quality-report.json`을 쓴다. `momentum.agent.quality.quarantine`은 격리 코드가 붙은 봉만 빼고 세션 시계·종목 상태·기업행동은 그대로 둔다.

| 코드 | 심각도 | 격리 | 뜻 |
| --- | --- | --- | --- |
| PARSE_ERROR | error | 행 | 날짜·숫자·시각·종목 기호를 읽을 수 없음 |
| NONPOSITIVE_PRICE | error | 행 | 시·고·저·종가 중 0 이하 |
| OHLC_INCONSISTENT | error | 행 | 저가 ≤ min(시,종) ≤ max(시,종) ≤ 고가 위반 |
| NEGATIVE_VOLUME | error | 행 | 거래량 음수 |
| AVAILABLE_BEFORE_CLOSE | error | 행 | 공개 시각이 그날 15:30 KST 이전(미래 정보 위험) |
| ADJUSTED_CLOSE_MISMATCH | error | 행 | 수정종가가 원시 종가와 다름(기업행동 회계 미구현) |
| DUPLICATE_ROW | error | 행 | 같은 세션·종목이 둘 이상. 어느 쪽도 고르지 않고 모두 보류 |
| ABNORMAL_RETURN | error | 봉 | 마지막 비격리 봉 대비 종가 변화가 ±30% 초과이고 그 사이 기업행동이 없음 |
| ACTION_EXPLAINED_RETURN | info | 아니오 | 위와 같은 변화를 그 사이 권리락일의 기업행동이 설명함 |
| MISSING_BAR | warning | 아니오 | 첫 봉 이후 세션에 봉이 없음(마지막 봉 이후는 상태가 NORMAL일 때만) |
| HALTED_NO_BAR | info | 아니오 | 거래정지(SUSPENDED) 상태라 봉이 없음 |
| UNKNOWN_SECURITY_STATE | warning | 아니오 | 그 세션 16:00 KST에 공개된 종목 상태가 없음 |
| ZERO_VOLUME | info | 아니오 | 거래량 0 |

±30%는 KRX 일일 가격제한폭이다. 정확히 30%는 정상 상한가로 본다. 이상 수익률은 **마지막으로 격리되지 않은 봉**과 비교한다. 하루짜리 튀는 값은 그날만 격리되고, 설명되지 않는 영구적 수준 변화(예: 누락된 분할)는 이후 봉이 모두 격리되어 가짜 모멘텀으로 들어가지 않는다. 정정 공시·정정 시세의 이벤트화는 다음 작업이다.
