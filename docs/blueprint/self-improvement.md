# 자기학습·기억·개선 알고리즘

기준: [블루프린트](README.md). 현재 구현 근거는 [`LogicProposer`](../../apps/kis-agent/src/trading_agent/logic.py), [`ResearchAgent`](../../src/momentum/agent/service.py), [통합 회귀 테스트](../../tests/unit/test_agent.py)다. 현재 동작과 향후 학습 기능을 구분한다.

## 1. 무엇이 스스로 바뀌는가

| 대상 | 현재 자동 변경 | 향후 방향 |
| --- | --- | --- |
| lookback | 사전 등록된 값 중 선택 | 개발 전용 가설 생성기, 범위 확장은 별도 정책 버전 |
| ranking | 등록된 3가지 규칙 중 선택 | 추가 특징·신호군은 별도 전략 ID와 검증 예산 |
| 연구 champion | 독립 검증 통과 시 revision 증가 | 시장·전략군별 registry, 운용 버전과 분리 |
| 가중치·선택 수·위험 한도·비용·합격 기준 | 자동 변경 안 함 | 새 정책 연구로 평가. 기존 holdout 재사용 금지 |
| 실패 기록의 자동 해석 | 결과 저장만 구현 | 실패 분류·중복 제안 억제·개발 가설 추천 |
| ML 가중치·예측 모델 재학습 | 미구현 | 시간 분할·라벨 격리·재현 가능한 제한 학습 |
| 소스 코드 | 자동 수정 안 함 | 코드 후보는 별도 격리 개발·회귀 검증 후 새 빌드로 취급 |

따라서 현재 수준은 **기록을 남기는 제한된 탐색·선택**이다. 자동 반복 자체를 모델 학습이나 새로운 알파의 발견으로 표시하지 않는다.

## 2. 후보 생성과 특징

기본 탐색 공간은 lookback `{5, 10, 20}` × ranking 3개다. 초기 champion은 lookback 10, momentum, 2개 슬롯, 총 비중 0.8, 최소 모멘텀 0이다. 기본적으로 총 9개 조합이며 현재 champion을 제외한 challenger 예산은 8개다. 정책상 허용되는 lookback은 2~60이나, 한 연구에서 임의로 전체 2~60을 재탐색하지 않는다.

```text
momentum(L) = close[t] / close[t-L] - 1
volatility = 20세션 일 수익률의 모집단 표준편차
positive_fraction = 같은 특징 창에서 양수인 일 수익률의 비율

momentum ranking       = momentum
risk_adjusted ranking  = momentum / max(volatility, 0.001)
trend_stability ranking = momentum × positive_fraction
```

모든 규칙에 같은 제외 필터·예산·체결·비용을 적용한다. 점수 내림차순, 동점이면 종목명 순이다. 평가기는 **매 세션** 전일 16:00 관측으로 다시 선정하고 리밸런싱한다. 이 주기는 지금 암묵적 고정값이며, 회전율·비용 해석의 전제이므로 `LOOP-02`에서 전략의 명시 파라미터(`decision_cadence`)로 올린다. 결정 주기는 후보 쪽 변수이고, 체결 시각을 정하는 실행 시계는 모든 후보에 공통이다([루프 계약](loop-contracts.md) §2). 후보 생성은 현재 고정된 그리드다. 직전 실패를 읽고 새 규칙을 발명하거나 범위를 자동 확대하지 않는다.

## 3. 데이터 사용권과 평가 일정

현재 기본 세션 번호를 1부터 세면 다음과 같다.

| 구간 | 최초 사이클 | 다음 사이클 |
| --- | --- | --- |
| warmup | 1~61 | 평가 시작 전 이력을 사용 |
| 개발 | 62~181, 40세션 fold 3개 | 127~246의 최근 120세션 |
| 격리 | 182~186 | 247~251 |
| 최종 검증 | 187~226 | 252~291 |
| 전진 shadow | 227~246 | 292~311 |

후속 개발에는 이미 본 과거 최종 구간을 사용할 수 있다. 그 다음 최종 구간은 새로운 예약 구간이어야 한다. 과거 구간의 역할을 미공개 최종 평가로 되돌리지 않는다. 파일 끝에 더 많은 데이터가 있어도 제안·개발 평가에는 개발 끝 시점의 prefix만 전달한다.

현재 격리는 고정 5세션이다. 학습형 모델·다른 보유 주기·미래 라벨이 추가되면 이 숫자가 충분하다고 가정하지 않는다. 라벨의 수익 구간이 훈련과 평가 사이에 겹치지 않도록 purge/embargo를 다시 정한다(`RES-02`). lookback 과거 창의 겹침과 미래 정답 라벨의 겹침은 다른 문제다.

## 4. 실제 사이클 순서

```text
1. 연구의 소스·정책·champion revision과 기존 prefix를 확인한다.
2. 고정 일정의 새 최종 구간이 모두 도착했는지 확인한다. 부족하면 대기한다.
3. manifest를 저장하고 시장 단위 최종 구간을 예약·소비 처리한다.
4. 개발 prefix에서 champion과 후보를 동일 조건으로 평가한다.
5. 활동·낙폭 조건을 통과하고 개발 점수가 더 좋은 단일 후보를 선택한다.
6. 후보가 있으면 같은 최종 구간에서 baseline/candidate와 각각의 비용 스트레스를 평가한다.
7. 완성 증거·해시를 먼저 저장한다.
8. 증거·계약·소비·revision을 재확인하고 champion 갱신 또는 유지를 기록한다.
9. 고정된 이후 shadow 구간에서 기존/신규 전략을 비교한다.
```

현재는 개발에서 개선 후보가 없어도 예약된 최종 구간을 돌려주지 않는다. 오류·중단·폐기에서도 소비 이력은 남는다. 덕분에 데이터·연구 이름·실행 경로를 바꿔 재도전하는 동작을 막는다.

초기 소스·정책은 연구 생성 시 고정하지만 cycle manifest 자체는 현재 최종 구간이 도착한 뒤 계산 전에 저장한다. 물리적인 평가 격리나 미래 결과 도착 전의 외부 commitment는 아직 없다. 따라서 현재 결과의 증거 등급은 **E1(예약 과거 구간)**이다([블루프린트](README.md) §5). `RES-03`에서 선택 후보까지 고정해 평가 구간의 첫 실행 시각 전에 저장하는 `EvaluationCommitment`([루프 계약](loop-contracts.md) §7)를 추가해 E2를 가능하게 하고, 보고서에 등급을 남긴다.

## 5. 개발 점수와 최종 승격

개발 점수는 **각 fold 일 수익률 평균의 평균**이다. 현재 Sharpe·복합 효용·시장 국면별 점수로 선택하지 않는다. fold별 초기 자본은 동일하고 포지션은 초기화한다. 조건을 통과한 후보 중 최고 점수를 고르되 champion보다 엄격히 높지 않으면 기존 전략을 선택한다.

| gate | 현재 조건 | 해석상 주의 |
| --- | --- | --- |
| 새 후보 | 후보 버전 ≠ champion 버전 | 단순 재등록 승격 방지 |
| 개발 우위 | candidate score > champion score | 개발 선택 근거 |
| 개발 위험 | 모든 fold의 최대 낙폭 중 최댓값 ≤ 20% | 연구용 기본값, 실계좌 일일 손절 기준이 아님 |
| 개발 활동 | 각 fold 체결 기록 ≥ 2개 | 독립적인 매매 기회 2개라는 뜻은 아님 |
| 최종 순개선 | candidate net return − baseline net return ≥ 0.001 | 0.1%p 차이. 단독 합격 조건이 아님 |
| 통계 | paired block 구간의 하한 > 0 | 추정 가정·블록 길이·표본 의존 |
| 최종 낙폭 | candidate drawdown ≤ 20% | 수익 크기와 함께 판단 |
| 비용 스트레스 | 2배 commission/slippage에서 candidate가 baseline보다 높음 | 세금 자체는 현재 2배로 만들지 않음 |
| 최종 활동 | 후보 체결 기록 ≥ 4개 | round trip 또는 독립 표본 수가 아님 |
| 관측 수 | 미리 정한 holdout 세션 수와 일치 | 기본 40, 테스트 성공 예제는 별도 등록한 80 |

현재 비교군은 **기존 champion**이다. 후보가 손실을 보더라도 기존 전략보다 충분히 덜 손해면 통과 가능하다. 현금·단순 ETF·동일 노출의 기준 전략 대비 우위나 양의 절대 수익을 요구하는 gate는 아직 없다. `RES-01`에서 새로운 평가 정책으로 추가한다. 과거 결과를 보고 기준을 소급 조정하지 않는다.

## 6. 통계와 탐색 예산

현재 일 수익률 차이를 날짜별로 정렬해 paired circular block bootstrap을 수행한다. 기본 블록 5세션, 2,000회, seed 0이다. 연구 최대 사이클 8회에 대해 family_alpha 0.05를 나눠 사용한다.

```text
단일 사이클의 양쪽 꼬리 예산 = 0.05 / (2 × 8) = 0.003125
검사 구간: 경험적 0.3125% ~ 99.6875% 분위수
승격: 하한 > 0 및 나머지 gate 전체 통과
```

이는 KIS 과거 단일 연구기의 고정 95% 구간과 다르며, 미국 H1~H4 Holm 검정도 아니다. 정상성·자기상관·블록 선택·분포 변화의 영향을 받는다. 코드는 연구용 추정 구간을 제공하며 통계적 보장을 확정하지 않는다.

현재 통계 gate의 해석상 주의(`LOOP-07`에서 정책 v2로 정리):

| 항목 | 현재 동작 | 정리 방향 |
| --- | --- | --- |
| 단측/양측 | 꼬리 예산은 양측으로 나누지만 승격에는 하한(`> 0`)만 쓴다. 따라서 **명목상** 단측 family 예산은 0.05가 아니라 0.025다. 이는 설계상 예산일 뿐, 데이터 의존성·비정상성·유한 재표집·다른 gate의 영향 때문에 실제 오류율이 0.025라는 보장은 아니다 | 단측 검정임을 명시하고 예산을 단측으로 정의. 실제 오류율은 null 시뮬레이션으로 따로 확인 |
| 분위수 추정 | 2,000회 재표집에서 하한은 재표집 분포 아래쪽 약 6번째 값(0.3125% 분위수)으로 정해진다. 독립 관측 6개라는 뜻이 아니라, 극단 분위수를 적은 재표집 값으로 추정한다는 뜻이다. seed 0으로 재현은 되지만 seed·재표집 수에 따라 흔들릴 수 있다 | 여러 seed·재표집 수에서 하한의 안정성을 확인하고, 그 결과로 재표집 수 하한을 정함 |
| 지표 역할 | 신뢰구간은 일 수익률 차이 평균, 순개선 gate는 누적 순수익률 차이. 단위가 다르지만 역할(주 검정 / 경제적 최소 효과)이 문서에 정의되지 않았다 | [루프 계약](loop-contracts.md) §6 지표 정의 표로 역할·단위 고정 |
| 블록 길이 | 5세션 고정 | **개발 구간에서** 블록 민감도를 확인해 고정. 보유 기간(`holding_horizon`)은 입력 중 하나일 뿐 그것만으로 정하지 않음(RES-02) |

정책 v2 완료 조건: null 시뮬레이션에서 명목 예산 대비 실제 승격률 보고, 여러 seed·재표집 수의 하한 안정성, 개발 구간에서 고정한 블록 민감도. 기존 연구의 정책은 소급해 바꾸지 않는다. 위 정리는 새 정책 버전과 예산 계정의 명시적 할당으로 적용한다.

현재 예산은 **한 연구에 등록한 최대 사이클**이다. 서로 다른 연구의 모든 탐색·모델·비용·국면 변형을 평생 합산하는 전역 alpha 관리까지 구현된 것은 아니다. `RES-03`에서 전략군·연구 버전 간 예산을 연결한다. 현재 시장 단위 소비는 보수적으로 다른 연구의 같은 날짜 사용도 차단한다. 나중에 같은 독립 표본에서 여러 전략을 비교하려면 관측 전에 하나의 연구군과 다중 비교 계약으로 등록해야 한다.

## 7. 연구 champion과 전진 관찰

완성 평가 증거가 저장된 뒤에만 revision을 갱신한다. 갱신 중 충돌이 생기면 새 계산으로 덮어쓰지 않는다. 복구에서는 저장된 gate와 manifest·소비 이력·소스·후보 공간을 확인하고, 최종 표본을 다시 열지 않는다.

현재 shadow는 새 구간에서 별도 초기 자본으로 시작한 champion과 직전 champion의 비교다. 부분 데이터가 늘면 같은 블록 시작점에서 재현한다. 전진 보고서의 열화 표시 조건은 낙폭 초과 또는 기존 전략보다 낮은 수익이다. 이 flag가 watcher나 주문 엔진을 자동 정지·rollback시키지는 않는다.

현재 shadow의 한계:

- champion을 유지한 사이클은 `champion_before == champion_after`라서 같은 전략끼리 비교한다. 순우위는 항상 0이고, 열화 flag는 낙폭 조건으로만 켜진다.
- 열화 flag는 기존 전략보다 1원만 낮아도 켜진다. 임계값과 지속 기간이 없다.
- shadow 구간(기본 사이클 1의 227~246)은 다음 사이클 개발 구간(127~246)에 포함된다. shadow는 승격 권한이 없으므로 독립 검증 위반은 아니지만, 이 재사용을 계약으로 명시한다([블루프린트](README.md) §5).

**목표 (`LOOP-04`, `LOOP-05`, `LOOP-06`):** champion을 `(market, family_lineage)` 단위로 관리한다. 비교용 실험 원장(구간마다 초기화)과 별도로, revision이 바뀌어도 현금·보유·배당채권을 이어 가며 교체 비용을 기록하는 관찰 원장을 둔다. 20세션 초기화 블록을 이어 붙여 연속 NAV로 쓰지 않는다. 유지 사이클의 비교 대상은 기준 전략이고, 열화 상태 전이는 사전 등록한다. 관찰은 주문 권한 없는 `ObservationRelease`로 시작한다. 계약은 [루프 계약](loop-contracts.md) §8, §10, §11에 있다.

**목표 (`OPS-05~06`):** 관찰 전략 버전·계좌 상태·데이터·selector·비용을 묶고, 위험 제어와 관찰 중단을 영속화한다. rollback도 이미 검증한 버전과 별도 운용 계약을 사용하며 과거 독립 구간을 다시 합격시키지 않는다.

## 8. 기억의 종류와 향후 저장 구조

아래의 새 테이블/파일명은 설계안이다. 현재 agent DB에 이미 존재한다고 해석하지 않는다.

| 기억 | 현재 | 추가할 내용 |
| --- | --- | --- |
| 사실 기억 | 데이터·정책·코드 해시, 소비 구간 | 공급자 품질·필드 커버리지·실행 환경 ID |
| 실험 기억 | trials, folds, gate 결과, champion revision | 정규화된 후보 ID, 연구군·상위 가설·시도 비용 |
| 실패 기억 | 후보 FAILED 사유와 gate, 실패 cycle 상태 | `failure_cases`: 원인 코드·재발 조건·후속 조치·노출 데이터 범위 |
| 개발 지식 | 고정 제안 metadata | `development_findings`: 개발 구간 증거와 반증 조건 |
| 관찰 기억 | shadow 수익·낙폭·선정·열화 flag | 모델/특징 drift, 계좌 대사, 기대/실제 비용 차이 |
| 결정 기억 | 갱신·유지·이력 가져오기 이벤트 | 정책 변경 이유·검증 예산·운용 전환 기록 |

최종 구간의 결과는 감사·운영 판단에 보존한다. 그 결과를 이용해 후보를 수정했다면 같은 구간은 다시 독립 평가에 사용할 수 없다. 모델 입력에서도 개발 메모리와 최종 평가 증거 저장소를 구분한다.

중복 여부는 가설·데이터 버전·개발 구간·정책·모델을 묶어 판단한다. 이전 국면에서 실패했다는 이유로 한 파라미터를 영구 금지하지 않는다. 새로운 개발 자료에서 다시 검토할 때도 시도를 기록하고 새로운 평가 예산·독립 구간을 사용한다.

## 9. 실패 → 개선 가설의 규칙

| 실패 유형 | 다음 개발 가설의 예 | 고정할 것 / 다음 검증 |
| --- | --- | --- |
| 데이터 누락·상태 미상 | 수집/정규화 수정, 커버리지 확대 | 수익 개선으로 분류하지 않음. 원본·소비 이력 보존 |
| 회전율·비용 열세 | 개발에서 리밸런싱·진입 완충 구간 가설 | 실제 비용을 낮추지 않음. 별도 후보·새 표본 |
| 특정 개발 fold의 낙폭 | 변동성·노출 제약을 별도 전략군으로 연구 | 기존 위험 기준 변경은 새 정책, 자동 완화 금지 |
| 신뢰구간 하한 ≤ 0 | 증거 부족으로 유지, 새 데이터 대기 | 검증 표본을 보고 길이·블록을 골라 합격시키지 않음 |
| holdout 성과 악화 | 기존 champion 유지, 원인 분류 | 같은 최종 구간으로 후보를 재선택하지 않음 |
| forward 열화 | 관찰·데이터·비용·국면 변화 조사 | root flag는 자동 운용 중단 기능이 아님 |
| 주문 상태 UNKNOWN | 체결·주문 읽기 대사 | 모델 학습 문제가 아님. 자동 재전송 금지 |

## 10. 학습 기능의 확장 순서

| 단계 | 구현 방식 | 진입 조건 | 현재 |
| --- | --- | --- | --- |
| L0 제한된 탐색·선택 | 고정 grid + 같은 평가 + champion revision | 현재 계약 | 구현·합성 검증 |
| L1 실패를 이용한 제안 | 개발 실패 코드·중복 시도·탐색 예산으로 후보 순서 제안 | 실제 데이터·비용·분류 기록 | 미착수 |
| L2 개발 전용 LLM 보조 | strict JSON, 허용 필드, 모델/프롬프트 버전·호출 예산, 결과 캐시 | 검증 표본/자격증명/코드 실행 권한과 분리 | 기존 앱 일부 코드, 통합 미연결 |
| L3 제한된 통계·ML 학습 | 사전 정의 특징·라벨, 학습/보정/선택/최종 구간 분리, pipeline snapshot | 시간 분할·누수 검사·학습 재현·단순 모델 비교 | 미착수 |
| L4 코드 개선 후보 | 격리 분기, 테스트·명세·환경 고정, 새 빌드로 평가 | 데이터·검증·배포 통제 성숙 | 현 개발 범위 밖 |

LLM이 과거 시장 사실을 알고 있을 수 있으므로 과거 파일을 숨겼다는 이유만으로 완전 미노출 표본이라고 단정하지 않는다. 모델 기반 제안의 최종 증거는 출처·노출 이력과 실제 새 전진 데이터를 함께 남긴다.

### 제한된 ML 학습의 구체 계약 — 미구현

1. **표본:** 영구 종목 ID × 관측 시각. 같은 날짜의 공통 시장 충격을 보존하고 종목 행을 무작위로 섞어 독립 표본으로 취급하지 않는다.
2. **특징:** 그 시각까지 공개된 모멘텀·변동성·거래대금·spread·상태만 사용한다. 필드 목록·윈도·결측 규칙·변환 코드를 먼저 고정한다.
3. **정답:** 관측 다음 실행 가능 시가부터 사전 정의한 h세션 뒤 실행 시가까지의 수익 등으로 정의한다. 미래 가격은 라벨 생성에만 사용한다. 목표 기간·비용·미체결 라벨의 의미를 명시한다.
4. **시간 분리:** train → calibration/validation → candidate selection → 최종 표본을 구분한다. h에 따라 라벨이 경계를 넘어가지 않도록 purge/embargo를 둔다.
5. **학습:** 단순 선형/정규화 모델부터 시작한다. 스케일·결측 변환·특징 선택도 train에서만 fit한다. 하이퍼파라미터·seed 시도 전체를 예산에 포함한다.
6. **평가:** 예측 정확도만으로 승격하지 않고 실제 전략 변환 후 같은 체결·비용·자본·비교군으로 평가한다. 현재 규칙 전략보다 복잡해진 대가도 기록한다.
7. **보존:** 가중치·변환기·특징 코드·환경·학습 구간·입력 ID·라벨 계약·선택 이유를 하나의 학습 artifact로 저장한다.
8. **재학습:** 새 개발 자료와 사전 등록한 주기가 충족될 때만 수행한다. 하루 손실이나 최종 표본의 실패를 보고 즉석에서 정답·임계값·위험 한도를 바꾸지 않는다.

이는 현재 `momentum-agent`가 실행하는 학습 코드가 아니다. RES-06의 구현·회귀·전진 검증 후에만 학습 단계가 완료된 것으로 표시한다.
