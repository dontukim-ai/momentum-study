## 2. 분봉 5개 (분 i까지의 값만)

- **분봉:** KIS 1분봉의 시가·고가·저가·종가·거래량이다.
  - 종가와 거래량은 v12 격자와 같다(마지막 체결가, 체결 없는 분은 직전 종가 유지·거래량 0).
  - 체결이 없는 분은 시가·고가·저가도 직전 종가로 둔다. 거래가 없었으니 움직임도 0이라는 정의이고, 값을 채워 넣는 것이 아니다.
- **표본 시점:** 09:30~15:14의 매분이다.
  - 09:30부터인 이유: 거래량 기준 창(직전 20분)에 09:00 시가 동시호가가 들어가지 않게 한다.
  - 15:14까지인 이유: 5분 뒤가 15:19 안에 들어와야 한다.
- **신호 25개:** 분 i−4~i의 다섯 봉 각각에 대해 아래 다섯 값을 쓴다.

  | 신호 | 정의 | 잘라내는 범위 |
  |---|---|---|
  | ret | 종가 ÷ 직전 분 종가 − 1, bp | ±100 |
  | body | (종가 − 시가) ÷ 시가, bp | ±100 |
  | upper | (고가 − max(시가, 종가)) ÷ 시가, bp | ±100 |
  | lower | (min(시가, 종가) − 저가) ÷ 시가, bp | ±100 |
  | vol | log((거래량 + 1) ÷ (분 i−24~i−5 평균 거래량 + 1)) | ±5 |

- **대상:** 다음 5분 방향, sign(종가[i+5] ÷ 종가[i] − 1)이다. 오름·같음·내림 셋이고, 정확도는 오르거나 내린 경우로만 계산한다. 같음 비율은 따로 낸다.

## 3. 모형 (4개, 모수 고정)

| 모형 | 내용 |
|---|---|
| BASE | 학습 기간에 더 많았던 방향 |
| PATTERN | 다섯 봉의 ret 부호(오름·같음·내림)에 거래량 상태(다섯 vol 평균 > 0이면 1)를 더한 486가지 패턴. 패턴마다 다음 5분이 오른 빈도를 라플라스 보정으로 구한다(v12 MARKOV 적합 재사용) |
| LOGIT | 25개 신호의 L2 로지스틱 회귀(v12 LOGIT 적합 재사용, 같은 벌점) |
| KNN | 25개 신호를 학습 기간 평균·표준편차로 표준화한다. 유클리드 거리로 가장 가까운 과거 200개 표본(오르거나 내린 것만)에서 오른 비율을 구하고, (오름 + 1) ÷ (200 + 2)로 보정한다 |

예측확률이 정확히 0.5면 예측하지 않는다(v12와 같다).

## 10. v19b 온라인 패턴 등록 (2026-10-29 사용자 요청, 데이터를 보기 전, v19 결과를 본 뒤)

사용자 요청(2026-10-29)은 두 가지다.
- 패턴 학습을 아래처럼 진행한다.
  1. 기존과 다른 유형이 나오면 새 패턴으로 등록한다.
  2. 같은 유형인데 결과가 다르면 그 패턴의 확률을 기록한다.
- 오름·내림의 **크기**와 **거래량**을 패턴 변인에 넣는다.

v19 PATTERN은 부호만 봤고 동결 뒤에는 확률을 갱신하지 않는다. 그래서 v19를 고치지 않고, 새 칸 **v19b ONLINE**으로 등록한다.

**v19 개발 결과를 본 뒤의 등록이라는 점을 밝혀 둔다.** v19 PATTERN은 50.31%였다. v19b의 판정은 아래와 같이 전진 데이터로만 한다.

### 10.1 봉 하나의 유형 (10가지)

- **크기 기준:** 분 i−23~i−5의 1분 수익 중 0이 아닌 것의 절댓값 중앙값(bp)이다. 0이 아닌 수익이 없으면 기준은 0이다.
  - 이 창은 v19 거래량 기준 창 안에 있어서, 표본이 v19와 같다.
  - 종목과 시기에 따라 기준이 저절로 맞춰지도록, 고정 bp를 쓰지 않는다.
- **움직임 5단계:**

  | 단계 | 조건 |
  |---|---|
  | 큰 내림 | 1분 수익 < 0이고 절댓값 > 기준 |
  | 작은 내림 | 1분 수익 < 0이고 절댓값 ≤ 기준 |
  | 그대로 | 1분 수익 = 0 |
  | 작은 오름 | 1분 수익 > 0이고 절댓값 ≤ 기준 |
  | 큰 오름 | 1분 수익 > 0이고 절댓값 > 기준 |

- **거래량 2단계:** 그 봉의 거래량이 v19 기준(분 i−24~i−5 평균)보다 많으면 많음, 아니면 적음
- 봉 하나 = 움직임 5단계 × 거래량 2단계 = **10가지**. 봉 다섯 개면 패턴은 최대 10⁵ = 100,000가지다.

### 10.2 등록과 확률 기록 (사용자 요청 1·2)

- **기록:** 패턴마다 그 뒤 5분이 오른 횟수와 내린 횟수를 센다. 같음은 세지 않는다.
- **새 패턴 (1):** 처음 나온 패턴은 그 결과가 확인되는 순간 기록이 생긴다.
- **같은 패턴, 다른 결과 (2):** 결과가 확인될 때마다 그 패턴의 횟수에 더한다.
- **확률:** 오를 확률 = (오른 횟수 + 1) ÷ (전체 + 2)
- **뒤로 물러나기:** 10만 가지 중 대부분은 드물게 나온다. 그래서 같은 방식으로 직전 4·3·2·1개 봉의 패턴도 함께 기록한다.
  - 예측할 때는 가장 긴 패턴부터 보고, 기록이 **20회 이상**인 첫 길이의 확률을 쓴다.
  - 1개 봉 패턴도 20회 미만이면 예측하지 않는다.
- **결과가 확인되는 시점:** 분 i의 결과는 분 i+5 종가로 확인된다. 분 j에서 예측할 때는 i+5 ≤ j인 결과만 기록에 들어가 있다. 같은 날 앞선 결과도 쓰지만, 미래 결과는 쓰지 않는다.

- 비용과의 비교는 v19 §5와 같이 보고만 한다.
- **시험 장부:** 예측 칸 1개(`v19b/ONLINE h5`)를 등록한다. 장부는 66개 시험이 된다.

### 10.4 실행 (맥)


### 10.5 일 단위 전진 갱신과 보고 (2026-10-29 사용자 결정)

- **매 거래일 장 마감 뒤(16:10 KST 이후)** 맥에서 `tools/v19b_daily.sh`를 실행한다. 맥 터미널의 launchd·cron 예약으로 돌린다(operations §12).
- **스크립트가 하는 일:**
  1. 069500 분봉을 2026-10-26부터 그날까지 받는다(KIS 읽기, 이미 받은 날은 다시 받지 않는다).
  2. `online-score`로 개발 구간 기록에서 시작해 모든 전진 날을 처음부터 다시 갱신한다. 결정적 계산이라 매일 다시 해도 결과가 같다.

- **첫 실행 실패와 수정 (2026-10-29):** 첫 실행(16:25)은 수집 도구가 "오늘"을 거부해 실패했다(`need start <= end < today`). 결과 txt에 그대로 남았다. 수집 도구가 15:40 KST 이후에는 당일을 받도록 고쳤다(`last_collectable`). 동시호가 체결이 찍힌 뒤라 그날 분봉이 완성돼 있다.
